# Asset Policy

Nothing from a game is ever stored in this repository. Everything is built on the user's machine from files the user supplies.

## Not allowed

- game assets of any kind: models, textures, shaders, audio, video, text, archives;
- the executable or any part of it;
- anything derived from those: converted assets, disassembly, shader dumps, extracted tables, screenshots.

## Allowed

- Leonida's own code that understands formats;
- build identities such as a BLAKE3 hash or CodeView GUID and age;
- per-build offsets of hooked functions, under names Leonida chooses;
- byte-pattern signatures and small interoperability constants;
- synthetic test data generated by Leonida's own code.

## Format tables

The BCPack decoder needs constant tables that are supplied separately. `cargo run --package leonida-tasks -- tables` downloads and verifies them into `Crates/Formats/Source/BcPackTables.bin`, which git ignores. Without the file, Leonida still builds and reports BCPack textures as undecodable.

## Where data lives

Outside the repository, configured in `Leonida.toml` or the `LEONIDA_*` environment variables: the game directory, the cache directory and the data directory.

## Enforcement

1. `.gitignore` keeps common data types out of `git status`.
2. `cargo run --package leonida-tasks -- policy` allows only small text files of known types, rejects binary signatures and long encoded runs, and checks PascalCase names and the no-comment rule.
3. Every runtime writer calls `leonida_core::ensure_outside_repo`, which refuses paths below a folder containing `.LeonidaRoot`.
4. Tests that need real files read their paths from environment variables and skip when unset.
